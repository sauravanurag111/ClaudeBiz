Architecture & implementation notes

Dealflow: how it's built

Claude does the thinking and writing. Dealflow does everything else. There are no AI keys in the code or configuration.

How it works: system flow

The same flow as the README diagram: Claude writes, Dealflow stores and sends, the client acts on a public link, and a scheduled ping keeps reminders on time.

Data flow

  1. Owner → Claude: "Quote Meesho for a logo redesign…". Claude reads the tool descriptions Dealflow publishes over MCP and writes the content.
  2. Claude → Dealflow: POST /mcp/:key → create_quote. The key in the URL identifies the account. Dealflow validates the input with zod schemas, computes totals and numbering (Q-0001), saves to Postgres, logs an event, and returns the public and edit links.
  3. Owner → Dealflow: edits in /app/quotes/:id. Changes are saved and logged as field-level events. The client page always shows the latest version.
  4. Client → Dealflow: GET /q/:publicId records the view, excluding the owner and link-preview bots. POST …/accept stores the name and timestamp, assigns INV-0001, sets the due date and shows payment instructions. POST …/paid flags "client says paid".
  5. Scheduler → client: due reminders are claimed atomically (FOR UPDATE SKIP LOCKED), their placeholders ({{amount}}, {{link}}…) are filled in, and they're emailed through Brevo. Paid or declined quotes cancel pending reminders.
  6. Claude ← Dealflow: list_quotes / get_quote return live status so Claude can report and draft follow-ups.

Tools used

Runtime: Node.js 20+, Express 5, @modelcontextprotocol/sdk (Streamable HTTP server, stateless), zod (tool input schemas), pg (Postgres). Frontend: server-rendered HTML with about 120 lines of vanilla JS for the line-item editor, copy buttons and local time zones. No framework, no build step. Security: scrypt password hashing and HMAC-signed HttpOnly session cookies, both from Node's built-in crypto; everything is HTML-escaped; public IDs are random 12-character strings. Infra: Render (web service and Postgres), Brevo (email), cron-job.org. Build tooling: Claude Code helped write the code. That's allowed by the brief, and none of it runs inside the product.

Assumptions

  • Customers already have a Claude plan with custom connectors (MCP). Dealflow adds no AI cost.
  • Small businesses in India mostly get paid by UPI or bank transfer, so showing payment instructions is enough for v1.
  • One owner per account; amounts are in the quote's own currency with no FX conversion.

Limitations (v1)

  • Render free Postgres expires after 30 days, and free instances sleep without the cron ping (a cold start of about 50 s could time out a Claude tool call).
  • The connector URL is a bearer secret. It can be reset from the Connect page, except on the shared demo account, which is pinned so anyone can try it.
  • No rate limiting, file attachments or multi-user teams yet. Dashboard totals are grouped per currency.

Next steps

  2. WhatsApp reminders and per-client reminder preferences.
